REPLAY

From the repository root:

  source ~/.zprofile
  python3 translation/check_phase2.py

For one file and all its imports:

  python3 translation/check_phase2.py --files ppg_finite_abstraction_repair

The command creates a fresh snapshot under ~/.local/state/pvs-checks. It uses
the saved .prf proofs with oracles disabled and replays the import chain. It
requires every reported formula and TCC to be proved-complete, checks that
declared lemmas are present in the report, and treats proof errors as failures.
The source tree is not used as a PVS working directory. results.json gives
per-file results; totals.json counts formulas without duplicate imports;
manifest.json records the exact source/proof hashes, tool version, and scope.
A --files run is explicitly marked as a partial phase-2 check.

TYPE AND DEFINITION CONVENTIONS

Lean Prop is represented by bool, and proposition-valued relations by predicates.
PVS TYPE permits an empty carrier. TYPE+ is used only where an inhabited value
type is required. Finset becomes finite_set, with extensional membership.
A full finite universe is an explicit subtype parameter U satisfying forall x:
U(x); it represents Fintype without silently adding an inhabitant. Predicates
over U, list coverage, positivity, locality, and abstraction hypotheses remain
explicit. Decidability instances do not add mathematical assumptions in PVS.

Proof-carrying Lean constructors become ordinary datatypes restricted by
predicate subtypes. TCCs prove that each returned constructor satisfies its
contract. Lean structures used only through their fields become explicit
function parameters and conjunctions of the same field laws.

The new support theories use the standard PVS prelude and locally replayed
finite-set induction, sums, products, and minima. They introduce no project
AXIOM or ASSUMING blocks. Generic monoid laws are constraints on the supplied
operation; zero_identity and plus_ac prove those constraints for use in proofs.
The generic sum was adapted from the installed PVS finite_sets_sum theory,
with the induction dependency replaced by locally proved cardinality induction.

MODULE REVIEW

PPGraphBDD
  CoupledIn is shared support restricted to B. SameComponent is its least
  equivalence closure, implemented with the prelude EquivClos. compOf and
  componentFootprint retain their original membership conditions. The numeric
  LLL condition uses the actual finite product. Locality and noninterference
  are stated for arbitrary assignments and the same footprint agreement.

PPGraphBDDCost
  totalCost is the sum of local real costs. optCost is the attained minimum
  over an explicit full finite assignment universe; Value remains inhabited.
  This represents the finite assignment type in Lean, including V empty.
  The proof constructs the same footprint-based gluing and proves both bounds.

PPGraphBDDLaplacian
  bddAdj is the simple dependency graph on B, extended by isolated vertices
  outside B. Removing dependency self-loops does not change its closure.
  Graph reachability and SameComponent are proved equivalent. Connected
  components are represented by their actual vertex sets, the canonical
  equivalence classes of this graph restricted to B.

  lapMatrixAction(x,c) is sum over d in B of the edge contribution x(c)-x(d),
  the action of degree-minus-adjacency. Vectors are zero outside B, so the
  kernel has no coordinates contributed by the ambient carrier outside B.
  A finite maximum argument proves that kernel vectors are constant on each
  component. Evaluation at a component representative and assignment of one
  coefficient to each component are proved inverse and linear.

  The final theorem uses HasFiniteDimension(kernel, card(components)), the
  finite-coordinate characterization of dimension, in place of Mathlib's
  numeric Module.finrank expression. HasFiniteDimension is defined independently
  of graphs: an index set of cardinality n and a real linear coordinate
  isomorphism. Its laws include inverse maps and independence from coordinates
  outside the finite index set. The proof supplies these maps explicitly.
  This is the dimension statement via a coordinate witness, not a translation
  of Mathlib's general finrank API or a postulated spectral identity.

PPGraphBDDCount
  graphClass = compOf is proved before identifying the two finite families.
  compGroup chooses a representative of a nonempty graph component; its
  membership and nonempty-domain obligations are proved. Injectivity,
  surjectivity, cardinality equality, and safe_parallel_units follow.

PPGraphBDDMatrix
  The incidence matrix has entries 0 or 1. Its Gram entry is an actual finite
  dot product, proved equal to the cardinality of the shared support. The full
  variable universe represents Fintype V.

PPGraphBDDMoserTardos
  ppg_mt_semantics defines resampling, the recursive trajectory, and the local
  well-formedness condition. MTState is the dependent type [v: V -> (domain(v))],
  preserving coordinate-specific value domains. A common ambient Value with
  domain predicates represents Lean's dependent family; disjointly tagged
  values can represent different coordinate types. Only the structural MT
  lemmas needed here are ported; no probabilistic expectation claim is inferred.

PPGraphBDDPartition
  Distinct component groups cover B and are pairwise disjoint. The sum theorem
  remains generic over an arbitrary commutative additive monoid, including its
  zero and law constraints, rather than being specialized to real numbers.

PPGraphInfeasibility
  Satisfiable means an allowed state satisfying all members of B. Infeasible
  is its negation. Graph feasibility uses a supplied reachability relation
  and invariant, with the isolated-start hypothesis retained for repair.
  ppg_repair_semantics supplies the eight PPGraphRepair prerequisite results.

PPGraphFarkasCertificate
  Linear constraints and dual certificates use actual finite row/column sums.
  Nonnegative multipliers, zero weighted columns, and a negative weighted bound
  are explicit. The contradiction is derived by interchanging finite sums and
  monotonicity. Rational checking uses the rational subtype of real arithmetic.
  The graph corollaries retain the sound-relaxation hypothesis.

PPGraphFiniteFeasibility
  The recursive list search preserves order and duplicates. A failed search
  implies infeasibility only under explicit coverage of all allowed states.
  goodStates and goodCount use the full finite state universe. The coverCheck
  result retains its supplied rejecting-certificate function.

PPGraphInfeasibilityCounting
  rejectedStates are actual event sets, not dependency-graph approximations.
  exactGoodCount has integer type and is the signed inclusion-exclusion formula:
  card(admissible) minus the sum over nonempty subsets K of
  (-1)^(card(K)+1) times card(intersection of rejected events in K).
  paritySign is the recursive integer function for (-1)^n. nonemptySubsets
  removes the empty subset from the powerset, with its membership equivalence
  proved. common_rejected_member proves that intersecting with the admissible
  universe gives exactly the nonempty event intersection used by Lean.
  The formula is proved equal to goodCount; its integer TCC follows from that
  cardinality identity. goodMass is the actual weighted sum over goodStates.
  The converse zero-mass and positive-mass results keep strict positivity of
  every allowed atom weight. The examples include a feasible zero-mass model
  when that hypothesis is omitted.

PPGraphReachabilityRefutation
  Reach is an inductive reflexive transitive closure of the step relation.
  InvariantRefutation retains start membership, step closure, and exclusion
  of good states. Completeness uses the reachable set. The finite checker
  enumerates invariant subsets of the full finite universe. Conserved values
  and barrier corollaries retain their original preservation hypotheses.

PPGraphFiniteAbstraction
  StepSimulation maps steps and good states. ExactAbstraction additionally
  lifts each abstract step from the current concrete state and reflects good.
  Exactness is required for positive completeness and equivalence claims.
  abstractRefutationSearch returns the intersection of all refuting finite
  invariants when that family is nonempty. Its search and decision subtype
  obligations are proved; no state-space finiteness is imposed on State.

PPGraphFiniteAbstractionRepair
  GoodPath and pathTarget use lists of successor states. boundedPaths uses
  the supplied abstract-state enumeration, preserves its order and duplicates,
  and includes exactly the good paths within the bound. Increasing search
  chooses the least successful budget and the first candidate. The prelude
  natural minimum appears only in termination/type obligations of firstIndex;
  its recursive body tests successive natural numbers.
  executeAbstractPath uses the supplied local realize function at each step.
  It preserves validity and length, with no choice of a concrete target.
  The result subtype carries either that valid trace or a checked invariant.
  This package verifies the logical algorithm; it does not claim a separate
  PVSio compilation or performance benchmark of the complete finite-set search.

PPGraphRepairDecision and PPGraphCertifiedDecision
  Region predicates, finite checks, and classification preserve the original
  gap/region conditions. Certified search and assessment use dependent result
  subtypes, with every success and failure constructor obligation replayed.

PPGraphUnsatisfiableCore, PPGraphCorrectionDuality, and PPGraphFiniteCore
  Minimal cores and correction sets are defined by subset/minimality conditions.
  Existence uses finite cardinality minimization. The duality proofs keep the
  original satisfiability assumptions. Finite core checking enumerates the
  appropriate powersets and retains full state-universe coverage.

PPGraphBDDInfeasibility
  Locality plus the outside-footprint frame condition justifies gluing component
  solutions. The base assignment is explicitly quantified in componentwise
  satisfiability, infeasibility, and minimal-core statements: dropping it would
  incorrectly change the empty-assignment case. The construction chooses local
  component solutions and proves the assembled assignment is allowed and satisfies
  every obligation. Minimal unsatisfiable cores lie in one dependency component.

EXAMPLES AND SCOPE LIMITS

ppg_phase2_examples checks conflicting Boolean obligations, a feasible single
obligation, zero weights, duplicate and incomplete search enumerations, a concrete
one-step trace, and a finite refuting invariant. ppg_phase2_empty checks an empty
state carrier. These are proof regressions, in addition to replaying every theorem.

This work does not establish that all legacy theories in the repository have
complete proof chains, nor that all remaining phase-1 rows are finished. Existing
unrelated .pvs/.prf changes and the old Sterbenz dependency issues are outside this
phase. No commit or push is performed by the replay command.
